## Problem Statement

Разработчик решения расширяет SDK на документы. Их rate и overhead — вложенные
объекты, которые не должны заново определяться в каждом пакете документа.
Существующий Price описывает цену, а не курс валюты или накладные расходы.

## Solution

Два независимых публичных JSON-среза общей библиотеки model:
DocumentRate/DocumentRateRequest и DocumentOverhead/DocumentOverheadRequest.
Каждый можно использовать и проверить без HTTP-операций конкретного документа.
Это общие формы данных, без универсального исполнителя CRUD.

## User Stories

1. Как разработчик решения, я хочу прочитать ссылку на валюту документа, чтобы узнать его валюту без expand.
2. Как разработчик решения, я хочу понимать, что отсутствующий value в существующем rate означает курс 1, сохраняя компактную форму ответа.
3. Как разработчик решения, я хочу сохранить дробный курс, чтобы не терять точность формата Float.
4. Как разработчик решения, я хочу записать только currency, чтобы передать ссылку без ненужных полей.
5. Как разработчик решения, я хочу записать только value, чтобы сформировать частичный запрос.
6. Как разработчик решения, я хочу различать отсутствие rate, null и пустой объект, чтобы управлять точным JSON.
7. Как разработчик решения, я хочу явно отправить value:0, чтобы omitzero не скрыл заданное значение.
8. Как разработчик решения, я хочу прочитать сумму накладных расходов без пересчёта единиц.
9. Как разработчик решения, я хочу выбрать распределение по весу, объёму или цене через именованные константы.
10. Как разработчик решения, я хочу сохранить неизвестное значение распределения, чтобы чтение не ломалось при расширении API.
11. Как разработчик решения, я хочу отправить частичные накладные расходы, чтобы SDK не сливал объект локально.
12. Как разработчик решения, я хочу использовать обе JSON-библиотеки Go с одинаковым результатом.
13. Как сопровождающий SDK, я хочу независимые ожидаемые JSON, чтобы тесты обнаруживали ошибки сериализации.
14. Как разработчик решения, я хочу знать серверные последствия rate:null, чтобы не воспринимать это как локальное удаление ссылки.
15. Как сопровождающий SDK, я хочу завершать каждый общий тип самостоятельным ticket, чтобы документы могли подключать его независимо.

## Implementation Decisions

### Предлагаемые типы валюты

| JSON | Поле Go | Чтение DocumentRate | Запись DocumentRateRequest |
| --- | --- | --- | --- |
| currency | Currency | *model.Reference | model.Field[model.Reference] |
| value | Value | *float64 | model.Field[float64] |

Все Field используют omitzero. В корректном присутствующем rate отсутствие value
означает курс 1: сервер не передаёт value, равный 1. Поэтому Value — *float64 с omitzero,
а не обычный float64: nil сохраняет компактную форму, явный 0 остаётся отличимым.
Над полем нужен комментарий: «nil — курс 1: сервер не передаёт value, равный 1».
SDK не подставляет 1 в структуру/JSON. Это правило не означает курс 1 при отсутствии
всего rate и не задаёт default незаданному request-полю. JSON null декодируется в nil,
но не объявляется отдельным допустимым значением курса API. Число — курс, не сумма.

В ответе документа rate предлагается *model.DocumentRate с omitzero;
в запросах — model.Field[model.DocumentRateRequest] с omitzero.
Внутренние поля различают пропуск, null и значение; заданный пустой объект
остаётся {}. Обязательность currency в таблице ответа не вводит новой локальной
валидации полноты вложенного объекта. Неизвестные JSON-поля игнорируются.

rate:null в запросе документа может вернуть валюту по умолчанию и вызвать
серверный пересчёт цен, сумм и расходов. Кодек только передаёт null; не делает
расчётов, предварительного Get или обещаний о результате сервера.
Отдельная полноценная сущность Currency не требуется: используется Reference.

### Предлагаемые типы накладных расходов

| JSON | Поле Go | Чтение DocumentOverhead | Запись DocumentOverheadRequest |
| --- | --- | --- | --- |
| sum | Sum | float64 | model.Field[float64] |
| distribution | Distribution | model.OverheadDistribution | model.Field[model.OverheadDistribution] |

OverheadDistribution — именованный открытый string; константы
OverheadDistributionWeight="weight", OverheadDistributionVolume="volume",
OverheadDistributionPrice="price". Никакой подстановки default или локального
запрета неизвестной строки. Сервер определяет допустимость значения.
Sum сохраняет API Float в копейках без округления, конвертации и денежной арифметики.
float64 соответствует существующим ценам SDK и имеет ограничения двоичной точности.

Внешний overhead в модели документа — *model.DocumentOverhead;
в запросе — Field[model.DocumentOverheadRequest]. Пустой объект, null и
вложенный явный sum:0 сохраняются. Не добавлять глобальных правил null.
Распределённый overhead отдельной позиции — скаляр, не этот объект. Как все денежные
поля SDK он имеет float64, даже если таблица API указывает Int: примеры содержат 0.0.

### Утверждённые решения первой волны

- Публичные имена DocumentRate/DocumentOverhead и их отдельных request-типов.
- Представление необязательного rate.value через *float64 без default.
- Открытый тип распределения и отказ от финансовой арифметики в SDK.
- Допустимость вложенных null проверяет сервер; кодек сохраняет их форму.

## Testing Decisions

Согласованная граница — публичная JSON-сериализация/десериализация, как у
DateTime, Field, Address/AddressRequest и CompanyType; приватные функции не тестируются.
Проверять encoding/json и encoding/json/v2 на независимых literal/golden ожиданиях.

DocumentRate: currency со значимыми Meta, дробный и целый value, явные 0 и 1,
отсутствие value, null-ссылку, неизвестное поле, частичный/полный request,
внешний Field в состояниях unset/null/{} и значения с внутренними Field.
Не подставлять курс или валюту и не требовать HTTP.

Overhead: сумма 0, дробная сумма, все три константы и неизвестная строка,
пропуск/null/частичный/полный request, внешний Field и вложенные состояния.
Проверять, что сумма не пересчитывается. Моделирование серверного распределения
расходов или последствий rate:null в локальных тестах не требуется.

Каждый ticket: gofmt, go test -race -count=1 ./..., go vet ./... ./testdata,
git diff --check, независимые Standards/Spec review относительно исходного BASE.
