# 01: Получение UOM по ID

## What to build

Разработчик решения получает предустановленную или пользовательскую UOM по ID
через `uom.Service.Get` и читает согласованные поля ответа.
Это первый законченный срез: модель данных, публичный метод, тесты и описание поддержки.

Контракт: [spec UOM](../spec.md). Утверждённый образец — Product;
архитектуру, общие типы и транспорт не перерабатывать.

## Acceptance criteria

- [x] Модель `uom.UOM` содержит Meta типа model.Meta; ID, AccountID, Name,
  Description, Code и ExternalCode типа string; Updated типа model.DateTime;
  Owner и Group типа *model.Reference; Shared типа bool.
- [x] Ссылки и Updated оформлены по образцу Product. Code сохраняет ведущие нули
  и допускает буквы; преобразования в число нет.
- [x] Неизменённая upstream-фикстура UOM проверена через encoding/json и encoding/json/v2:
  проверяются значения всех согласованных полей, включая Shared=false, ссылки и Updated.
- [x] Добавлен один небольшой пример предустановленной UOM «дюйм», code=039,
  дословно из официальной документации, отдельно от upstream и со ссылкой на источник.
  Он проверяет отсутствие accountId, owner, group, shared и сохранение code="039".
  Не добавлять большую коллекцию или обновление upstream ради этого случая.
- [x] Отсутствующие поля читаются как нулевые значения. AccountID не объявляется
  обязательным на основании таблицы документации: противоречие с примерами разобрано в spec.
  Shared=false не используется для определения происхождения UOM.
- [x] Неизвестное поле ответа не мешает декодированию.
- [x] `uom.NewService` принимает *transport.Client, возвращает *Service и ошибку;
  nil client отклоняется, как в Product.
- [x] Get принимает context и ID, возвращает (*UOM, error), выполняет GET
  на entity/uom/{id} без дополнительных query-параметров и тела.
- [x] UUID проверяется по образцу Product, без ограничения версии. Неверный ID
  отклоняется до обращения к серверу; nil context и отмена обрабатываются существующим транспортом.
- [x] Локальные HTTP-тесты проверяют метод, маршрут, заголовки, обычный и gzip-ответ,
  возвращённые значения и отсутствие лишних запросов.
- [x] Успех требует HTTP 200 и непустой ID. Неожиданный статус, некорректный JSON,
  null и ответ без ID дают ошибку и nil вместо частично прочитанной модели.
- [x] Ошибки 4xx/5xx доступны через errors.As как *sdkerrors.APIError;
  исходные ошибки и отмена доступны через errors.Is, контекст операции сохранён,
  префикс moysklad: не дублируется. Автоматических повторов нет.
- [x] Документация возможностей SDK отражает Get UOM и текущие ограничения;
  Create/Update не объявлены реализованными заранее.
- [x] По завершении ticket пройдены форматирование, go test -race -count=1 ./...,
  go vet ./... ./testdata и git diff --check.

## Учебные шаги

Двигаться законченными файлами или этапами: полная модель чтения с фикстурами
и тестами; затем конструктор/Get с проверкой успешного ответа, валидации и ошибок.
Внутри этапа выполнить red/green без остановки между ними и без дробления по полям.
Объяснять назначение этапа и результат проверки. После завершённого этапа
останавливаться для разбора и ждать команды пользователя.

## Границы

Не добавлять Create/Update, List, Delete, expand, metadata, фасад или новые общие механизмы.
Не использовать живой аккаунт и .env. Реализация — один агент;
ревью и локальный commit выполняются после завершения всего ticket по правилам проекта.
Промежуточный незавершённый этап не коммитить. Новые решения контракта согласовывать.
