### Этап 3. Необязательные поля запросов

Новые файлы:

- `model/field.go`
- `model/field_test.go`

Шаги:

- [x] Согласовать общий тип поля запроса.
- [x] Представить три состояния: поле не передано, передан null, передано значение.
- [x] Проверить, что не теряются `false`, `0`, пустая строка и пустой массив.
- [x] Проверить кодирование с encoding/json/v2 и совместимость с encoding/json.

Тип поля отвечает за представление состояния. Допустимость null у конкретного поля определяется контрактом API.

Контракт:

- `Field[T]` используется в моделях запросов с `omitzero`; нулевое значение — «не передано». В общей модели Attribute поля Value/File также используют Field.
- Конструкторы `Value(v)` и `Null[T]()`; чтение состояния через `IsZero`, `IsNull` и `Get`.
- Незаданное поле без `omitzero` возвращает ошибку; `omitempty` не используется вместо него.
- Методы `MarshalJSON`/`UnmarshalJSON` совместимы с json v1 и v2; внутри используется v2.
- Nil-слайс кодируется как `[]`, nil-map — как `{}`; `[]byte` использует Base64.
- `Value(DateTime{})`, nil-указатель и nil-интерфейс кодируются как `null` и после JSON roundtrip становятся Null.
- Отсутствующее поле сохраняет прежнее состояние при повторном декодировании в ту же структуру.
- Ошибка разбора значения внутри Field не меняет его состояние; атомарность всего внешнего Unmarshal не гарантируется.
- Обязательные поля CreateRequest остаются обычными типами; изменяемые поля UpdateRequest используют Field.

Автоматические проверки и ревью пользователя пройдены.

Управление определениями дополнительных полей через metadata откладываем.

Value хранится как `Field[jsontext.Value]`, File — как `Field[AttributeFile]`; тип остаётся открытой строкой.
AsLong разбирает значение напрямую в int64. Геттеры AsString/AsBool/AsLong/AsDouble/AsTime/AsReference проверяют тип; неизвестный тип не ломает чтение сущности.
AsReference возвращает Meta и Name без проверки совпадения type с meta.type (для product возможны service/bundle).
AttrValue возвращает ошибку кодирования; AttrNull/AttrFile/AttrFileNull создают отдельные формы запроса.
Секунды даты не обрезаются клиентом: точность до минут — контракт хранения на сервере.

### Передача контекста в новую сессию

- Go 1.27, основной кодек — encoding/json/v2; общие JSON-типы проверяются и с encoding/json.
- Product.Get/Create/Update реализованы для узкого набора полей из README. Общая схема запроса остаётся приватной в product.
- DateTime хранит time.Time, использует Europe/Moscow с историческими смещениями; fallback +03:00 и tzdata описаны в README.
- Field различает отсутствие/null/значение; обязательный тег — omitzero. Attribute сохраняет сырое value, AsLong не проходит через float64.
- Цены — float64 в сотых долях валюты. Сервер сливает salePrices и attributes, пустые массивы их не очищают.
- Golden заданы вручную; канонизация не округляет целые числа. Upstream остаётся неизменённым снимком с версией в docs/upstream.md.
- Примеры записи защищены флагом и маркером тестового товара. Реальных Create/Update не выполняли.
- Проверки: go test -race -count=1 ./..., go vet ./... ./testdata, gofmt, git diff --check.
- Продолжение: после ревью и коммита этапов 5–9 начать масштабирование моделей entity, context и report небольшими группами.
- List/пагинацию, query, заголовки, retry/429 и остальные универсальные механизмы добавлять по мере необходимости; expand отложен.
- Не выполнять реальную запись без отдельного согласия. Новые изменения коммитить после ревью пользователя.
