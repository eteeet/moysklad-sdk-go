- [x] Решить совместимость с RFC 3339 из официальной фикстуры.

Контракт:

- Именованный тип поверх `time.Time`, методы `MarshalJSON`/`UnmarshalJSON` совместимы с json v1 и v2.
- `Europe/Moscow` загружается через `sync.OnceValue`; при недоступной tzdata используется фиксированный MSK +03:00 с потерей исторических смещений.
- Чтение принимает формат API и RFC 3339; запись использует только формат API с тремя знаками миллисекунд, без округления.
- `null` и пустая строка сбрасывают дату в нулевое значение; нулевое значение записывается как `null`.
- `IsZero` обеспечивает работу `omitzero`; `MarshalText` не добавляется.
- Особенности контейнеров и подключение `time/tzdata` описаны в README.

Автоматические проверки и ревью пользователя пройдены.

Upstream-фикстуры не изменяем ради совместимости с реализацией SDK.

### Этап 3. Необязательные поля запросов

Новые файлы:

- `model/field.go`
- `model/field_test.go`

Шаги:

- [x] Согласовать общий тип поля запроса.
- [x] Представить три состояния: поле не передано, передан null, передано значение.
- [x] Проверить, что не теряются `false`, `0`, пустая строка и пустой массив.
- [x] Проверить кодирование с encoding/json/v2 и совместимость с encoding/json.

Тип поля отвечает за представление состояния. Допустимость null у конкретного поля определяется контрактом API.

Контракт:

- `Field[T]` используется только в моделях запросов с `omitzero`; нулевое значение — «не передано».
- Конструкторы `Value(v)` и `Null[T]()`; чтение состояния через `IsZero`, `IsNull` и `Get`.
- Незаданное поле без `omitzero` возвращает ошибку; `omitempty` не используется вместо него.
- Методы `MarshalJSON`/`UnmarshalJSON` совместимы с json v1 и v2; внутри используется v2.
- Nil-слайс кодируется как `[]`, nil-map — как `{}`; `[]byte` использует Base64.
- `Value(DateTime{})`, nil-указатель и nil-интерфейс кодируются как `null` и после JSON roundtrip становятся Null.
- Отсутствующее поле сохраняет прежнее состояние при повторном декодировании в ту же структуру.
- Ошибка разбора значения внутри Field не меняет его состояние; атомарность всего внешнего Unmarshal не гарантируется.
- Обязательные поля CreateRequest остаются обычными типами; изменяемые поля UpdateRequest используют Field.

Автоматические проверки и ревью пользователя пройдены.

Отдельную библиотеку денежных вычислений на этом этапе не строим.

Контракт:

- `Price` используется для buyPrice и minPrice; `SalePrice` дополнительно содержит PriceType.
- Value — `float64` в копейках (сотых долях валюты), без конвертации валют и денежной арифметики в SDK.
- Нулевой Value не пропускается. Незаполненные Currency и PriceType пропускаются через `omitzero`.
- Currency — Reference; PriceType содержит Meta, ID, Name, ExternalCode и допускает заполнение только Meta.
- Одни типы используются для чтения и внутри моделей запросов; необязательность внешнего поля обеспечивает Field.
- Проверяются оба JSON-кодека, `500.0`, дробные значения, большой пример из документации, нулевая цена и стык с Field.
- Для чтения используются неизменённые upstream-фикстуры product.json, product_full.json и price_type.json.
- Подключение к Product — этап 6; правила обновления salePrices — этап 8.

Автоматические проверки и ревью пользователя пройдены.
