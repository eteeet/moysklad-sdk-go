## Общие правила денежных полей

Все денежные поля SDK — float64 в копейках независимо от Int/Float в таблице API.
Официальные примеры Supply/Demand содержат overhead:0.0; integer-поле отвергает такое
число обоими JSON-кодеками. Для денег проверяем 0, 0.0 и дробь, не обещаем точность
integer за пределами 2^53. Это не относится к ID, счётчикам, ставке vat и сырым Attribute
long.
Валютный курс — не денежная сумма; его отсутствие имеет отдельный контракт DocumentRate.

Контракт:

- `Field[T]` используется в моделях запросов с `omitzero`; нулевое значение — «не передано».
  В общей модели Attribute поля Value/File также используют Field.

- Nil-слайс кодируется как `[]`, nil-map — как `{}`; `[]byte` использует Base64.
- `Value(DateTime{})`, nil-указатель и nil-интерфейс кодируются как `null` и после JSON
  roundtrip становятся Null.
- Отсутствующее поле сохраняет прежнее состояние при повторном декодировании в ту же
  структуру.
- Ошибка разбора значения внутри Field не меняет его состояние; атомарность всего внешнего
  Unmarshal не гарантируется.
- Обязательные поля CreateRequest остаются обычными типами; изменяемые поля UpdateRequest
  используют Field.

### Передача контекста в новую сессию

- Go 1.27, основной кодек — encoding/json/v2; общие JSON-типы проверяются и с encoding/json.
- Product.Get/Create/Update реализованы для узкого набора полей из README. Общая схема
  запроса остаётся приватной в product.
- DateTime хранит time.Time, использует Europe/Moscow с историческими смещениями; fallback
  +03:00 и tzdata описаны в README.
- Field различает отсутствие/null/значение; обязательный тег — omitzero. Attribute сохраняет
  сырое value, AsLong не проходит через float64.
- Цены — float64 в сотых долях валюты. Сервер сливает salePrices и attributes, пустые
  массивы их не очищают.
- Golden заданы вручную; канонизация не округляет целые числа. Upstream остаётся
  неизменённым снимком с версией в docs/upstream.md.
- Примеры записи защищены флагом и маркером тестового товара. Реальных Create/Update не
  выполняли.
- Проверки: go test -race -count=1 ./..., go vet ./... ./testdata, gofmt, git diff --check.
- Продолжение: после ревью и коммита этапов 5–9 начать масштабирование моделей entity,
  context и report небольшими группами.
- List/пагинацию, query, заголовки, retry/429 и остальные универсальные механизмы добавлять
  по мере необходимости; expand отложен.
- Не выполнять реальную запись без отдельного согласия. Новые изменения коммитить после
  ревью пользователя.

Точные поля чтения и записи, особенности серверного поведения и TODO перечислены
в документации каждого пакета. SyncID Counterparty/Organization читается и доступен
в CreateRequest/UpdateRequest через Field[string]. Unset пропускается, значение/пустая
строка/null сохраняются; запрет изменения после заполнения проверяет сервер без скрытого
Get.
JSON-контракт проверен обоими codecs, SyncID-only Update — локальным HTTP-сервером,
включая APIError и отсутствие повторов. Очистка/перезапись SyncID не обещаются.
bonusPoints, salesAmount и isEgaisEnable — только для чтения.

В срезы не входят счета, контактные лица, события, файлы и discounts Counterparty,
региональные объекты реквизитов, остальные настройки НДС, подписи/печать,
fsrarId и utmUrl Organization. Expand также отложен; List — [transport.md](transport.md),
Delete и массовые операции — [write-async.md](write-async.md).

Публичные JSON-контракты проверены обоими кодеками; методы — локальным HTTP-сервером
с настоящим transport. Живой аккаунт не использовался.
